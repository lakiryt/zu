# 検討: 線に向かう線と、曲がる線(2026-11-08)

二つの要望について検討した。一つは、線に向かって線を引くこと(債権者から「詐害行為」の矢印へ、424条の取消の矢印を引くなど)。もう一つは、線を曲げること。今の線の決まりは [lines.md](lines.md) と SPEC.md の「線」に書いてある。

## 線に向かう線

`as` で名前を付け、中点を狙う形で入れた(2026-11-08。仕様は SPEC.md の「線」)。以下は検討の記録。

### 検討した時点

できなかった。線の端には図形の名前しか書けず、線には名前がなかった。ラベルが空の `text` を線の上に置いて結べば似た形にはなるが、線の中点に合わせるには数が要った。

### 決めること

1. 線をどう指すか(線に名前を付ける書き方)
2. 線のどこに当てるか
3. どの順に置くか(当てる先の線を先に置く)

### 1. 線の指し方

| 案 | 書き方 | 良い点 | 気になる点 |
| --- | --- | --- | --- |
| A. 後ろに `as` | `b ---> c "詐害行為" as f`<br>`x ---> f "取消"` | 線の文の後ろに足すだけで、`into` と同じ並びになる。指す側は今の書き方のまま | 語が1つ増える |
| B. 前に名前 | `f: b ---> c` | 名前が目に付く | 字句に `:` を足す。図形の文(`text a …`)と並びが違う |
| C. Mermaid に寄せる | `b f@---> c` | Mermaid 11 の線の名前(`A e1@--> B`)に近い | 読みにくい。線の記号の字句を広げることになる |
| D. ラベルで指す | `x ---> "詐害行為"` | 名前が要らない | ラベルのない線や、同じラベルの線を指せない。ラベルを直すと壊れる |
| E. 両端で指す | `x ---> (b c)` | 名前が要らない | 同じ2つを結ぶ線が複数あると決まらない |

推すのは A。

- 線の名前は図形の名前と同じ空間に置く。同じ名前があれば誤りにする
- 指す側は図形と同じく `x ---> f` と書ける。`f ---> g`(線から線へ)も書ける
- 例:

```
text b "債務者(B)"
text c "受益者(C)" right of b by 200
text x "債権者(X)" above b
b ---> c "詐害行為" as f
x ---> f "424条 取消"
```

### 2. 当てる場所

推す決まり:

- 当てる先の線の中点を狙う。線のラベルが中点(線の上)にあれば、ラベルの下地の縁で止める。詐害行為の例なら、矢印は「詐害行為」の字に当たる。ラベルが脇に逃げているか、ラベルがなければ、線そのものに当てる
- 止める位置は線に触れる所(間は 0〜2)。図形のように 6 空けると、細い線では離れて見えるため
- 自分の側の端は今と同じく、図形の本体の外枠の手前で止める
- 線の側の `into` は意味がないので誤りにする

中点の代わりに、相手の線上で自分にいちばん近い点に当てる案もある。ただ、ラベルに当てられなくなり、相手の図形が動くと当たる位置が端の方へずれる。そのため中点を推す。中点以外を指す書き方(線の 30% の所など)は、要るまで入れない。

### 3. 置く順

- まず図形どうしの線を、ラベルまで今と同じに置く。次に、線に向かう線を、当てる先が決まったものから順に置く
- 線どうしで循環する(`f` が `g` に向かい、`g` が `f` に向かう)のと、自分自身に向かうのは誤りにする
- 線に向かう線のラベルも、先に置いたものを避ける(今の仕組みのまま)
- 図形の間を自動で広げる決まり(`position.ts` の `roomFor`)には数えない。図形の位置は線に左右されないという今の決まりを保つ。間が足りなければ `by` で広げる
- 同じ組を平行にずらす決まりは、(図形, 線) の組にも今と同じに使う

### エディタ

- 線1本と図形1つ(または線2本)を選んで「線でつなぐ」。名前のない線には、結ぶ前に `as f1` のような名前を自動で付ける
- 線のパネルに名前の欄を足す。名前を変えたら、その線を指す線も書き換える。線を消したら、その線に向かう線も消す(図形と同じ扱い)

## 曲がる線

### 種類

1. 弧: 2点をなめらかに結ぶ曲線(「ぐにゃっと」曲げる)。三角形の図で本人と相手方の線を外へ逃がす、平行にずらす代わりに曲げて分ける、間の図形をよける、といった使い方
2. 直角に折れる線(L 字、コの字)。表や系図のような図向け
3. 通る点を決めた線。どんな形にもできる

まず 1 を入れる。2 と 3 は、書き方の見通しだけ付けておく。

### 弧の書き方

B(TikZ 式)の `bend left` / `bend right` で入れた(2026-11-08。仕様は SPEC.md の「線」)。大きさの語、角、描き方は下の検討のとおり。`as` と `bend` は順を問わず、`into` だけは最後に書く(残りの語を図形の名前として読むので)。

ふくらむ向きと大きさを語で書き、数は書かない。

```
a ---> c "効果帰属" bend above
a ---> c bend below large
```

| 案 | 書き方 | 良い点 | 気になる点 |
| --- | --- | --- | --- |
| A. ふくらむ向きを上下左右で | `bend above` / `below` / `left` / `right` | 置き方(`below a`)と同じ語で、図を見たまま書ける。a と c を入れ替えても形が変わらない | 真横の線に `left`/`right`、真縦の線に `above`/`below` は使えないので誤りにする |
| B. 進む向きから見た左右 | `bend left` / `right`(TikZ と同じ) | どの向きの線にも使える | 向きを入れ替えると逆にふくらむ(エディタの入れ替えで直す必要がある)。図を見て書くとき迷う |

推したのは A だったが、B(TikZ 式)に決めた(2026-11-08、利用者の判断)。見本は Artifact「bend の向き見本」で見せた。以下の A の細目は記録として残す。

- 斜めの線は、上にふくらむ側が `above` になる。右上がりの線なら、`above` と `left` は同じ側を指す
- 大きさは `small` / `medium`(既定)/ `large`。端で線が弦からなす角を 15° / 30° / 45° にする。角で決めるので、長い線でも短い線でも同じ形に見える

### 描き方

- 2次ベジェ曲線(SVG の `Q`)で描く。制御点は弦の中点から、ふくらむ向きへ「弦の長さ / 2 × tan(角)」の所
- 図形の縁で切る所は、曲線を細かい折れ線にして求める。矢先の向きは、端での接線にする
- ラベルの候補は曲線の中点(ふくらみの頂点)から試す。脇の候補はその点の法線の向きに取る
- 曲げた線は、同じ組を平行にずらす決まりから外す(ふくらみで分かれるので)
- `into` の端は、接線の向きで刺す
- 図の範囲には、ふくらみの頂点も含める
- 二重線の弧は、端と制御点を法線の向きに半分ずつずらした2本で近似する。ゆるい弧なら見分けがつかない
- 線に向かう線が曲げた線を指すときは、曲線の中点に当てる

### 折れる線(後で)

書き方は後で決める。TikZ の `-|`(横に出てから縦)と `|-`(縦に出てから横)が参考になる。語にするなら `a ---> b elbow` に、どちらへ先に出るかを添える形が考えられる。

### 通る点(後で)

見えない点の図形(`point p below a` など)を今の置き方で置き、`a ---> b via p` で通らせる。置き方の仕組みをそのまま使えるので、数を書かずに形を決められる。

### エディタ

- 線のパネルに「曲げる: なし / 左 / 右」と大きさの選択を足す。B に決めたので、向きの入れ替えでは left と right も入れ替えて形を保つ
- 線の中ほどをドラッグして曲げる操作も考えられる。放したら、近い向きと大きさの語に寄せる

## 決めたこと(2026-11-08)

1. 線の名前は `as f`
2. 線に向ける線は中点を狙う。中点にラベルがあればラベルに当てる
3. 曲げる向きは B(進む向きから見た左右、TikZ 式)
4. 線に向かう線を先に入れ、弧を次に入れる

入れてから分かったこと:

- 同じ線に向けた端は、中点に集まって重なるので、その線に沿って 12 ずつ離すことにした
- 同じ図形に刺さる端(`into`)を離すのは、同じ回に置く線どうしだけ。線に向けた線が先に置いた線と同じ図形に刺さると、離れないことがある
- 図形を線の近くに置く書き方(`above f` など)はない。債権者を「詐害行為」の真上に置くには、今は揃えや数を使う
- 弧の端は図形の手前で切るので、引いた弧の端で弦となす角は、決めた角(15°、30°、45°)より少し浅い。角は本体の中心どうしを結ぶ弧で決めている
- 弧に向けた線は頂点を狙い、複数あれば頂点での接線に沿って離す(弧からわずかに離れるが、12 の間隔なら見分けがつかない)

## into で触れさせる(2026-11-08)

線に向けた線の端は、図形と同じく手前(6)で止め、`into` に挙げたときだけ触れさせる(二重線なら2本の間まで入る)。図形では「into がなければ手前で止め、あれば中まで入る」なので、線にも同じ決まりを当てた。決まりが1つで済み、触れているかどうかが書き方に表れる([principles.md](principles.md))。
