# 検討: 数値に頼らない置き方(2026-11-07)

方針: 書く人が座標や px の数を考えずに済むようにする。数値は逃げ道として残すが、例や文書では使わない。Mermaid の調べは [research/mermaid-layout.md](../research/mermaid-layout.md)。

## 今の仕様で数値が要る場面

- `at x y`: 絶対座標。ただし出力では、いちばん左上の図形が余白のすぐ内側に来るよう全体をずらすので、原点そのものに意味はない。効くのは `at` どうしの差だけ。原点がすべての図形の外に来ることもあるが、見えない
- `by 80`: 隣との間(外枠どうしの距離、px)
- `size 120 60`: 大きさ(px)

`at` を書かなければ座標は出てこない。残るのは `by` と `size` の数。

## 問題: 相対配置だけでは「同じ段」に揃わない

`below a` は「a の真下で、a の下端から間を空ける」という意味なので、基準ごとに段の高さが変わる。当時の `examples/agency.zu` で実際に起きていた:

```
text a "本人(A)" at 0 0
text c "相手方(C)" right of a by 240
text b "代理人(B)" below a by 100
parallelogram land "甲土地" below c by 100
```

b と land は同じ段に見えてほしいが、出力の中心の y は b が 206.8、land が 225.6 で、18.8 ずれる。b(文字、高さ 22.4)と land(平行四辺形、高さ 60)の高さが違い、どちらも基準の下端から 100 空けて置いたので、中心の高さが揃わない。

同じように、`cube item ... right of c` は外枠(ラベルを含む)の中心を c に揃えるので、立方体の本体は c より上にずれる。

数値で直そうとすると、書く人が高さを計算して `by` を変えることになる。数値に頼らない方針に反する。

## 案

### A. 並びの文(`row` / `column`)

```
row b land
```

挙げた図形を、書いた順に左から並べ、上下の中心を揃える。間は既定の間。`column` は縦に並べて左右の中心を揃える。block-beta の格子の「揃えが自動で効く」良いところを、格子にせずに取り入れる。

決めること:

- 並びの中の図形は、自分の置き方(`below a` など)を持てるか。持てるなら、並びとの食い違いをどう扱うか
- 並び全体をどこに置くか(`row b land below a` のように並び自体に置き方を付ける、など)
- 一つの図形が横の並びと縦の並びの両方に入れるか(入れると格子になる)

### B. 揃えの文(`align`)

```
text b "代理人(B)" below a
parallelogram land "甲土地" below c
align b land
```

位置はそれぞれの置き方で決め、`align` は片方の向き(ここでは上下)だけを揃える。今の文法を崩さずに足せる。

決めること:

- 揃えるときにどちらを動かすか(先に書いたほうに合わせる、など)。`below` の間と揃えは両方とも上下を決めるので、どちらかを優先しないと決まらない
- 横に揃えるのか縦に揃えるのかを、どう書くか(並び方から推すか、`align top` のように書くか)

### C. 段と列(格子)

block-beta のように、図全体を段と列で決める。揃えは確実に効く。ただし、自由な位置に置けることを優先して Mermaid から離れた経緯があるので、全体を格子にするのは方針に合わない。部分的に(入れ子で)使う形ならあり得る。

### 共通: 何を揃えるか

立方体はラベルを本体の下に置くので、外枠の中心と本体の中心が違う。揃えるのは本体(図形そのもの)にし、ラベルは揃えの計算から外すのが自然に見える。`right of` の上下の揃えも同じ考え方に変えるか、合わせて決める。

## 間の数をなくす案

- 段階の語: `below a far` のように、決まった数段階の間から選ぶ。語は分野に寄せない
- 図全体の設定: flowchart の `nodeSpacing` のように、既定の間を図ごとに一度だけ決める
- エディタでドラッグしたときは、既定の間の倍数にスナップさせ、数が散らからないようにする

## 決めたこと(2026-11-07)

- B(`align`)にした。今の「関係で置く」書き方をそのまま使え、揃えたいときだけ1行足せばよい
- 書き方は `align row …`(同じ段)と `align column …`(同じ列)。向きの語は省けない。省いたときにどちらになるかを覚えなくて済むようにした
- 揃えの基準は本体の中心にした。合わせて、相対配置の揃えと `at` も本体の中心に変えた(立方体がラベルのぶん上にずれる問題も直った)
- 合わせる先: `below` だけなら最も下、`above` だけなら最も上。これで、書いた間より基準に近づくことがない。`at` などの置き方の図形があれば、それに合わせる。詳しくは SPEC.md の「揃え」
- 配置の段は、x と y を別々に解くように作り直した。揃えは片方の軸だけを決めるので、こうしないと書けない

## 未決

- 間の段階の語を入れるか、入れるなら何段階でどう呼ぶか
- `below` と `above` が混ざる揃えでは、図形が基準に近づいたり重なったりし得る。誤りにするか、警告を出すか
- 揃えた図形どうしの左右の間(row で横に並ぶ図形の間)は揃えない。等間隔に並べたくなったら、別の文(A の `row` に近いもの)を考える
