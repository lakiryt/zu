# 検討: 視覚的なエディタ(2026-11-07)

ブラウザで図をクリック・ドラッグして配置を変え、その結果を .zu として書き出すエディタ。Vercel に静的サイトとして置く。まだ作っていない。

## 決めたこと

- **正本は .zu の文字列**。画面は文字と図の2枚。ドラッグは文字の該当箇所だけを書き換え、構文→配置→描画をやり直して図を描き直す。コメントや行の順番は崩さない。元に戻すは文字の履歴で持つ
- **ドラッグは既定でスナップさせ、数を書かせない**。自由にドラッグできると数(`at 123 456`、`by 87`)だらけの .zu ばかりになり、「数に頼らない」方針([placement.md](placement.md))に反する。ドラッグでできるのは基本的に関係の付け替えにする
  - 図形を別の図形の右・左・上・下に寄せると、`right of c` のような置き方を書く(間は既定)
  - 同じ段・同じ列に寄せると、`align row …` / `align column …` を足す
- **数を直接指定するのは高度なプロパティにする**。普段は見えないところ(詳細パネルなど)で `by` や `at`、`size` の値を入れられるようにする。数を書いた文は、図の上でも見分けがつくようにすると、数が増えていないか気づける
- 道具: 束ねるのに Vite を使う(開発用の依存。実行時の依存は増やさない)。`src/` をそのまま読み込む
- 保存は .zu の書き出しと読み込み(端末内のファイル)だけ。サーバーには何も送らない。論証ドリルのデータを利用者ごとに閉じる方針と合う

## 作るときに要るもの

- 構文の段で、置き方や揃えの文字の範囲(始まりと終わり)を持つ。今は始まりしか持っていない。書き換える箇所を特定するのに要る
- 配置の段の `Scene` は、各図形の本体の中心(`anchor`)を持つようになった。スナップの当たり判定に使える
- 配置の段は全体を余白の内側へずらす。ドラッグ中に左上の図形が動くと、他の図形まで画面上で動いて見える。ずらした量を `Scene` に持たせ、エディタ側で打ち消す
- 基準になっている図形を動かすと、従う図形もついてくる(関係で置いているので自然にそうなる)。基準だけを動かして従う図形を残す操作は後回し
