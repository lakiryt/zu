# 木(tree)(2026-11-10)

分類や体系(物権の種類、要件の分かれ方など)を、箇条書きから枝分かれする線の図にする。仕様は [SPEC.md](../../SPEC.md) の「木(`tree`)」。

## 求めた形

```
- 1
  - a
  - b
    - i
    - ii
- 2
```

から

```
┌1─┬─a
│   └─b─┬─i
│       └─ii
└─2
```

親は最初の子と同じ段に書き(`1─┬─a`)、上の段の項目は左の括弧でまとめる。

## 決めたこと

- **図の種類でなく、図形の種類にした**(`tree t` の後に項目の行)。Mermaid のように文書の頭で図の種類を宣言すると、木だけの文書しか書けない。図形にすれば、置き方、揃え、`caption`、注釈、ほかの図形からの線がそのまま効き、法律関係の図の脇に分類を添えられる。名前(`t`)を一つ書く手間は増える
- **項目は箇条書きの形(`- 文字`)で、引用符なしで書ける**。一行に一文の決まりは保ち、項目の行を `tree` の文の続きとして読む。行の頭の `- ` は今まで必ず誤りだったので、今までの文の読み方と重ならない(原則 7)。引用符で書けば、改行や `%%` も入れられる
- **ラベルは根**。`tree t "物権"` と書けば根から枝分かれし、書かなければ上の段の項目を括弧でまとめる(上の段が1つなら、その項目を根にして括弧を描かない)。ほかの図形でも、ラベルを省けばラベルなしなのと同じ考え
- **同じ深さの項目は同じ列に揃える**(原則 3「関係が形に表れる」)。親ごとに子の位置を決めると詰まるが、深さが揃わず段の違いが読みにくい。列の幅は、子を持つ項目のうち最も広いもので決める(子のない項目の右には何も来ないので数えない)
- 線は実線、矢印なし。鉛筆で描ける形(原則 1)
- 大きさ(`size`)は書けない。字と項目の数で決まる(`text` と同じ)
- 本体の中心は外枠の中心。置き方と揃えは、ほかの図形と同じく外枠で効く
- エディタでは一つの図形として選び、動かし、消す(項目の行も一緒に消える)。項目はパネルで `- 文字` の行のまま書き換える

## 決めていないこと

- 項目に名前を付けて、線や注釈を項目に向けること(例: 木の「所有権」から別の図形へ矢印)。今は木全体にしか結べない
- 向き(左から右のほかに、上から下の組織図の形)。語で選ぶなら `tree t down` など
- 項目の字の大きさ(`size small` で字を小さくする)。今は `size` を誤りにしている
- 項目の行の間のコメントは、エディタで木の文を書き換えると消える
- 括弧の形(縦線の代わりに `{` の形)。今は縦線と横線だけ
