# 版の付け方と出し方(2026-11-08)

zu はほかのプロジェクトが GitHub から入れて使う(`npm install github:lakiryt/zu`)。版を付けずに入れると master の最新が入り、書き方や見た目の変更が知らないうちに届く。そこで版に名前(タグ)を付け、入れる側はタグを指して入れる。

## 版の番号

[Semantic Versioning](https://semver.org/lang/ja/) に従う。1.0 までは試作なので、0.x の決まりを使う。

| 変更 | 0.x のあいだ | 1.0 から |
| --- | --- | --- |
| 互換を壊す変更 | 2つ目を上げる(0.2.0 → 0.3.0) | 1つ目を上げる |
| 互換を保つ追加 | 3つ目を上げる(0.2.0 → 0.2.1) | 2つ目を上げる |
| 直し | 3つ目を上げる | 3つ目を上げる |

「互換を壊す」は、版を上げると入れる側が困る変更。zu では次の3つを数える。

- **書き方**: 今まで通っていた `.zu` が誤りになる、または意味が変わる
- **見た目**: 同じ `.zu` から出る SVG の見た目がはっきり変わる(既定の大きさや間、線の引き方)。細かな位置のずれ(ラベルの置き場所の改善など)は数えない
- **公開するもの**: `src/index.ts` から出しているものを消す、名前を変える、型を狭める。構文木の型に必ず要る項目を足すのも含む(構文木を自分で組み立てる側が壊れるので)

エディタ(Law図)だけの変更は版を上げる理由にしない。エディタは master から Vercel に出す。

## 記録

- 変更は [CHANGELOG.md](../../CHANGELOG.md) の「未公開」に、作業のたびに書き足す。入れる側が読むものなので、書き方・見た目・公開するものの変化を書く。中の作り替えは書かない
- 互換を壊す変更には「**互換を壊す**」と付け、直し方(書き換え方)を添える
- コミットの題は `feat:`、`fix:`、`docs:`、`refactor:`、`build:`、`chore:` で始める(今まで通り)

## 出し方

1. CHANGELOG.md の「未公開」を新しい版の見出し(`## 0.3.0 (2026-11-20)`)に変え、空の「未公開」を上に足す
2. `package.json` の `version` を同じ番号にする(`npm version 0.3.0 --no-git-tag-version`)
3. SPEC.md の見出しの版を同じ番号にする
4. `chore: release v0.3.0` でコミットし、注釈付きのタグを付ける: `git tag -a v0.3.0 -m "v0.3.0"`
5. 送る: `git push && git push origin v0.3.0`

入れる側は `npm install github:lakiryt/zu#v0.3.0` のようにタグを指す。
